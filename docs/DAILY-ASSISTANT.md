# Ежедневная тренировка и разбор ошибки

## «Есть пять минут»

С главной страницы открывается одна подборка на местную календарную дату: восемь заданий, без выбора модуля и без предварительного показа ответов.

- Три примера на счёт. Пока нет хотя бы трёх ответов в быстром счёте с точностью от 70% без помощи, используется простой счёт.
- Повторение задач из уже попробованных тем, с приоритетом менее уверенных результатов и разнообразием модулей. Для нового ученика — вводные группы дробей, процентов и степеней.
- До двух ошибок с наступившим сроком повторения. Если их нет, места заполняются повторением. В практических задачах сохраняется полное общее условие и рисунок.

Выбор за день сохраняется; случайное возвращение на экран не меняет задачи. Незаконченная подборка переносится на следующий день, пока ученик её не завершит. Затем можно получить подборку текущей даты. Повторно завершить один день нельзя. Хранятся последние 60 результатов.

Таймер измеряет активное время на экране тренировки; фон приложения, экран объяснения и пауза в каталоге не учитываются. Время записывается каждые 15 секунд, при ответе, уходе с экрана и завершении. При аварийном закрытии возможна потеря последнего короткого отрезка времени, но уже записанные ответы сохраняются. Пять минут — ориентир: нет принудительной отправки ответа или штрафа. После хотя бы одного проверенного ответа можно закончить раньше; непройденные задачи не считаются ошибками.

Ответы и помощь учитываются в общей статистике соответствующих тем и групп сразу. Дневная тренировка не заменяет рекорд обычной десятки. Правильный самостоятельный ответ на запланированную прошлую ошибку продвигает тот же цикл закрепления, что отдельный режим повторения. Ожидающие задачи не получают преждевременный зачёт.

## Разбор конкретного шага

После проверки ответа доступна кнопка «Разобрать этот шаг». Всегда доступны условие, рисунок, идея, первый шаг и проверенное решение из банка, включая правильный ответ. Это работает без интернета.

Вопросы нейросети требуют отдельного подключения преподавателем. Пока нет сервера, интерфейс честно показывает этот статус и не подменяет нейросеть шаблонными ответами. После подключения есть предложенные вопросы и поле до 600 символов. Помощник получает только текущую задачу, введённый ответ и вопрос; общая история прогресса и данные ученика не отправляются.

Сервер сам находит задачу по модулю, группе и ID в своей копии банка. Присланные клиентом решения и правильные ответы не используются. Полный объект задачи содержит данные графиков, геометрии, общих условий и таблиц. Высокоприоритетная инструкция требует объяснять конкретный шаг по эталону, не придумывать ход ученика по одному итоговому ответу и сообщать о недостатке данных. Это уменьшает ошибки модели, но не доказывает математическую корректность её текста. Объяснение нейросети подписано отдельно; проверенное решение всегда остаётся рядом. Несовпадение эталонного ответа между сервером и приложением блокирует показ такого ответа.

## Запуск сервера преподавателя

В этой поставке есть готовый к запуску сервер. Оплаченный API, действующий ключ и VPS не входят в репозиторий и не создаются автоматически. Реальные ответы модели требуют их настройки; тесты используют имитацию провайдера.

Нужен Node.js 24. Сервер использует стандартные модули Node и `fetch`, без дополнительных npm-зависимостей. Банк задач импортируется из `src/` с поддержкой TypeScript в Node 24.

1. Скопируйте `server/.env.example` в `server/.env`. Этот файл исключён из Git и Docker-контекста.
2. Выполните `node server/issue-token.mjs` для каждого ученика. Сохраните выданный код и передайте ученику лично. В `ASSISTANT_TOKEN_HASHES` внесите JSON-массив SHA-256 кодов. Удаление хеша и перезапуск отзывают этот доступ.
3. В `server/.env` задайте `OPENAI_API_KEY` и `OPENAI_MODEL`. Выберите доступную вашему аккаунту модель, которая поддерживает Responses API и строгий JSON Schema. После выбора нужен отдельный прогон качества объяснений на задачах; код не предполагает универсального качества любой модели.
4. Для локальной проверки запустите `node --env-file=server/.env server/start.mjs`. По умолчанию слушает `127.0.0.1:8787`. `/health` проверяет процесс; `/v1/connection` требует Bearer-код и проверяет конфигурацию, не выполняя платный запрос. Доступность и квота внешнего API выясняются при первом объяснении.
5. Для рабочего Android-клиента нужен HTTPS. На VPS с Docker и доменом, направленным на сервер, заполните `ASSISTANT_DOMAIN` и выполните `docker compose --env-file server/.env -f server/compose.yml up -d --build`. Caddy завершает HTTPS; сам Node-порт наружу не публикуется. Порты 80/443 должны быть доступны.
6. В приложении откройте разбор → «Подключение преподавателя», введите `https://ваш-домен` и код ученика, нажмите «Проверить и сохранить». Пересборка APK для смены сервера не нужна.

Для обновления банка на сервере после `git pull` повторите команду сборки Docker. Не удаляйте том `assistant_limits`, если хотите сохранить дневные ограничения.

## Границы доступа и расходов

- Ключ провайдера используется только на сервере. Код ученика хранится в Android Keystore через Expo SecureStore; при удалении подключения удаляется с устройства. В веб-просмотре код хранится только в памяти до перезагрузки.
- Рабочий клиент разрешает только HTTPS без встроенных паролей, пути, query и fragment. HTTP разрешён только на loopback в отладочной сборке. Перенаправления запросов запрещены, чтобы не отправлять код другому адресу.
- У каждого кода по умолчанию максимум 6 попыток в минуту и 30 в сутки UTC; у всего сервера — 200 в сутки и до четырёх одновременно. Резервирование происходит до платного запроса, включая запросы, завершившиеся ошибкой провайдера. Дневные счётчики сохраняются атомарно в томе и переживают перезапуск. Это ограничение числа запросов, а не денежная квота; дополнительно установите бюджет в аккаунте провайдера.
- Выход ограничен 1800 токенами, ожидание сервера — 30 секунд. Отказ, неполный ответ, неверный формат и сбой провайдера дают ошибку без придуманного объяснения; локальное решение остаётся доступным.
- Нет автоматического логирования вопросов, ответов, кодов и ключей. У провайдера используется `store: false`; это не обещание отсутствия всех служебных журналов провайдера.
- Данная версия сервера рассчитана на один процесс. Для нескольких реплик нужен общий атомарный счётчик, например Redis. Коды дают доступ только к помощнику; это ещё не система аккаунтов, платежей или ограничения всего приложения по подписке.

Официальная документация: [OpenAI — генерация текста](https://developers.openai.com/api/docs/guides/text), [структурированный вывод](https://developers.openai.com/api/docs/guides/structured-outputs), [Expo SDK 57 SecureStore](https://docs.expo.dev/versions/v57.0.0/sdk/securestore/).

## Проверка

`npm run typecheck`, `npm run lint`, `npm test`. Тесты проверяют персональный подбор, возобновление, помощь и подсчёт результатов, интервалы повторения, миграцию, а также реальный локальный HTTP-сервер с имитацией внешнего API: авторизацию, канонический контекст, лимиты после перезапуска и ошибки провайдера. Проверка ответа настоящей модели и установка на физический Android требуют подключённого сервиса и устройства.

Интерфейс проверен в мобильном веб-представлении на 390 и 320 пикселях: полная подборка, неправильный ответ, помощь, перезагрузка с продолжением, обновление сроков ошибок, сохранение старых рекордов, досрочное завершение, пауза таймера на разборе, подключение и ответ имитированного помощника, обработка лимита. Горизонтального переполнения страницы и ошибок выполнения не обнаружено.
